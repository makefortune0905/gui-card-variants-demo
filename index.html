Agent GUI Card 是一套容器协议，不是一张业务定制卡

业务只传 tone、标题、副标题、内容原子和 actions。容器统一控制白底、圆角、间距、 最大高度、内部滚动、按钮布局和 PC/App 响应式规则。研发接入时不要在业务侧重新定义卡片样式。 

<AgentGuiCard
  tone="danger"
  title="出现阻塞型异常"
  subtitle="File src/main.py line 31..."
  maxHeight={{ pc: 180, app: 200 }}
  actions={[
    { label: "复制", variant: "outline" },
    { label: "重试", variant: "outline", priority: "primary" },
    { label: "取消", variant: "outline" },
  ]}
>
  <CardBodyText>错误信息来自异步任务执行链路...</CardBodyText>
</AgentGuiCard>
Container 只负责视觉、尺寸、滚动和响应式，是跨端规则的唯一来源。
Header 状态点/图标、标题、副标题、右侧图标按钮。只说明“发生了什么”。
Content 承载内容原子。解释原因、状态、上下文、选项或业务 Slot。
Footer 只放底部动作按钮。按钮全部描边，布局由容器宽度决定。

Content primitives 内容原子命名

内容区最终收敛为下面 8 类。建议组件名用 PascalCase，Props / contentType 用 camelCase。

正文段落 bodyText / CardBodyText 纯文本正文，不加框。用于 1-3 行解释、错误摘要、普通说明。
  • 默认继承正文色和行高
  • 长内容进入 Content 内滚
超链接 inlineLink / CardLink 正文中的轻量跳转。用于文档、仓库、任务单、日志入口。
  • 只强调可点击文本
  • 不要做成大按钮
辅助说明 helperText / CardHelperText 低权重补充信息。用于来源、时间、Agent 名称、上下文说明。
  • 颜色弱于正文
  • 不承担主信息
代码块 codeBlock / CardCodeBlock 代码、命令、日志、traceback。等宽字体，可横向滚动。
  • 可带语言和复制入口
  • 不要撑宽卡片
纯文本块 textPanel / CardTextPanel 有弱底色的文本容器。用于需要从正文中区隔出来的说明。
  • 比正文段落更强调
  • 不是所有正文都需要加框
Icon + 标题 iconTitle / CardIconTitle 图标加短标题。用于小节标题、步骤标题、状态标题。
  • 只放一行核心表达
  • 详细解释放后续正文
Banner 块 statusBanner / CardStatusBanner 横幅式反馈。用于授权成功、处理中、警告、轻提醒。
  • 可带图标和副文案
  • 不放复杂操作
操作块 inlineAction / CardInlineAction 内容区里的行内对象操作。用于路径、文件、资源项 + 小按钮。
  • 区别于 Footer 主操作
  • 按钮仍使用描边样式

结构规则

Container AgentGuiCard 白底、8px radius、无左色条；tone 只通过小圆点或轻量状态表达。容器负责 max-width、max-height、overflow 和按钮断点。
Header title / subtitle / iconAction 标题说明“发生了什么”，副标题说明来源或上下文。复杂文案、代码、列表不要塞进 Header。
Content children / contentType 只组合内容原子。正文段落默认不加框；代码、引用、Banner、文本块需要区隔时才加弱容器。
Footer actions 只放底部动作。按钮全部用 outline/ghost 的描边视觉；主次关系通过顺序、文案和轻量状态区分。

PC / App 响应式规则

App max-width: 280px 按钮始终纵向，填满容器。App 优先保证可读性和首屏多卡密度，不做横向按钮挤压。
PC max-width: 430px 按钮区宽度大于 280px 时横向等宽；小于等于 280px 时纵向等宽。
高度 maxHeight={{ pc, app }} PC 和 App 可分别配置最大高度。Content 内部滚动，Header 和 Footer 保持稳定可见。
按钮数量 actions.length 建议 Footer 露出 1-3 个入口；超过 3 个收敛到“更多”。复杂选择放 Content，最终确认放 Footer。
